01Google Earth · Interaction design, front end

Drag to select

One drag on the map to select any number of features, instead of a click per feature. The first way to select in bulk directly on Google Earth’s 3D map, built to fit with every existing way to select, on web and mobile.

01The problem

On the map, features could only be picked one at a time. The alternative was ticking them off in a list in the project panel. Styling dozens of features meant dozens of clicks, and complex workflows hit a wall.

Google Earth also needed a temporary drawing state for features on the way. Drag to select would be the first thing built on it, so it had to set the pattern.

02The work

Selection already worked three ways (checkboxes, dragging in the panel and clicking on the map), so the new gesture had to fit with all of them, across:

  • Web and mobile. One idea, two very different kinds of input.
  • Streamlined and productivity layouts. Simple by default, fast for power users.
  • Screen-centered drawing tools. Other tools also claim the middle of the map, so the gestures can’t collide.

Every conflict was worked out by prototyping, testing and iterating with a UX designer and a PM. The implementation, end to end, was one engineer.

03The result

Drag to select is live in Google Earth on the web. Select a whole neighborhood of features in one motion, then style them together. As the first feature on Earth’s new drawing state, it laid the groundwork for the drawing tools to come.
